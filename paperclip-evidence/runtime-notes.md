## 1. Control plane aur actual model runtime ki boundary

Paperclip agent ko apne andar ek naya foundation model bana kar execute nahi karta. Server ki responsibility admission, identity, issue ownership, environment/workspace preparation, instructions/skills/tool exposure, dispatch, durable event/result accounting, cancellation aur eventual task-state application hai. Actual provider interaction adapter/harness/backend ki responsibility hai. Is distinction ka concrete contract `ServerAdapterModule.execute(ctx): Promise<AdapterExecutionResult>` hai; optional environment tests, skills sync, session codec, models discovery, quota discovery aur config schema separate hooks hain (`E:/coding/code/Trade/paperclip/packages/adapter-utils/src/types.ts:508`). Interpretation: ek company agent ka organizational record aur uska selected AI runtime ek hi cheez nahi hain; adapter/provider ko swap karne ke liye normalized server contract diya gaya hai.

Fresh execution mein native runner automatic upgrade nahi hai. `resolveNativeRuntimeMode` explicit `paperclip_runner` adapter selection ko dekhta hai; direct adapters obsolete native config ke bawajood legacy path par rehte hain. Native eligibility mein experimental enablement aur special provider flags check hote hain. Cursor Cloud ke liye local controller requirement bhi encoded hai. Persisted native runs recovery ke samay apna transport retain karte hain, rollout flag disable hone se existing run legacy nahi ban jata (`E:/coding/code/Trade/paperclip/server/src/services/native-runtime/runtime-mode.ts:101`, `E:/coding/code/Trade/paperclip/server/src/services/native-runtime/runtime-mode.ts:136`, `E:/coding/code/Trade/paperclip/server/src/services/heartbeat.ts:3583`). Isliye “native” ko har adapter ka synonym kehna galat hoga.

Heartbeat orchestration actual branch `executeHeartbeatRuntime` tak pahunchti hai. Native path persisted native input aur runner instance ID maangta hai; missing selection par fail hota hai. Legacy branch selected `adapter.execute` ko run, runtime/config/context, execution target, runtime MCP/tools, identity, logs/events/usage callbacks aur cancellation signal pass karti hai (`E:/coding/code/Trade/paperclip/server/src/services/heartbeat.ts:3688`, `E:/coding/code/Trade/paperclip/server/src/services/heartbeat/runtime-execution.ts:551`, `E:/coding/code/Trade/paperclip/server/src/services/heartbeat/runtime-execution.ts:886`).
