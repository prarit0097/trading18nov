## Common request aur normalization pipeline

Equity price `historical` command decorator `EquityHistorical` model declare karta hai. Function command context, provider choice, standard aur extra parameters se `Query` banata hai, phir `OBBject.from_query` await karta hai; vendor HTTP logic is route function mein nahin hai. `Query` selected provider choices se leta hai aur standard-params class name se model name derive karta hai. Standard parameters aur supported non-default extras merge hote hain; unsupported explicitly supplied extras warning dete hain. Executor ko user settings ke credentials aur preferences milte hain. [[openbb_platform/extensions/equity/openbb_equity/price/price_router.py:44]] [[openbb_platform/core/openbb_core/app/query.py:28]] [[openbb_platform/core/openbb_core/app/query.py:36]] [[openbb_platform/core/openbb_core/app/query.py:66]]

Executor provider name lowercase karke registered provider find karta hai, then model-key se fetcher choose karta hai. Missing provider/model explicit errors hain. Credential filtering sirf chosen provider ke declared secrets nikalti hai aur required missing credentials ko extraction se pehle reject karti hai. Base `Provider` credential names ko provider prefix deta hai, jaise declared `api_key` FRED ke liye `fred_api_key` hota hai. Yeh data-vendor credentials hain; in code paths se exposed API server ki authentication policy infer nahin hoti. Async extractor override initialization par chosen implementation ban jaata hai; `maybe_coroutine` synchronous/asynchronous extraction handle karta hai. Streaming subclass ho to typed stream path use hota hai. Standard `EquityHistoricalQueryParams` symbol uppercase karta hai aur symbol/start/end define karta hai; output date, OHLC aur optional volume/vwap contract deta hai. Date parser time-bearing strings ko datetime aur baaki ko date banata hai. ## Adapter 1: Nasdaq historical, end to end

Equity domain installed hone par historical route se standard key Nasdaq fetcher tak resolve hoti hai. Adapter query ko `NasdaqEquityHistoricalQueryParams` mein validate karta hai, credentials required nahin rakhta, aur `gather_historical_prices(symbol, "stocks", start, end)` call karta hai. Optional output symbol multiple tickers support karta hai. Final stage raw rows ko `NasdaqEquityHistoricalData.model_validate` se typed standard-compatible rows banata hai. [[openbb_platform/providers/nasdaq/openbb_nasdaq/models/equity_historical.py:15]] [[openbb_platform/providers/nasdaq/openbb_nasdaq/models/equity_historical.py:41]]

Helper unspecified end ko today aur start ko end minus 365 days leta hai. URL mein historical asset class, dates aur default `limit=10000` jata hai. Is helper mein offset/page loop nahin hai; single response ko exhaustive history ka verified guarantee nahin keh sakte. Trades-table rows se date aur numeric OHLCV parse hote hain, unparsable session dates skip hoti hain aur date ordering lagti hai. Multi-symbol fan-out `asyncio.gather` use karta hai; individual error warning ke saath skipped symbol banta hai, sab empty hon to `EmptyDataError`. Returned series partial ho sakti hai. [[openbb_platform/providers/nasdaq/openbb_nasdaq/utils/helpers.py:496]] [[openbb_platform/providers/nasdaq/openbb_nasdaq/utils/helpers.py:532]] [[openbb_platform/providers/nasdaq/openbb_nasdaq/utils/helpers.py:604]]

SQLite cache successful GET HTTP-200 responses ke liye configured hai; default TTL 15 minutes, historical family 6 hours aur quote-info family 60 seconds hain. JSON request headers origin/referer aur generated user agent supply karte hain. Historical fetcher ke declared query fields mein cache bypass option nahin hai; helper-level `use_cache=False` ko user-facing historical parameter assume nahin karna chahiye. ## Timeouts, rate limits aur reliability boundaries

Shared async request helper default timeout 10 seconds rakhta hai, preferences ka request timeout accept karta hai, callback se deserialize karta hai aur owned session close karta hai. Batch helper concurrent requests gather karta hai aur failures/results aggregate karta hai; inspected helper mein universal retry/backoff/pagination loop nahin hai. Cboe aur Nasdaq historical flows mein explicit shared quota scheduler nazar nahin aata; iska matlab upstream unlimited hona nahin hai. [[openbb_platform/core/openbb_core/provider/utils/helpers.py:350]] [[openbb_platform/core/openbb_core/provider/utils/helpers.py:401]]

Provider-specific policies distinctly exist: SEC process-local limiter default nine requests/second aur environment override rakhta hai. FRED wrapper default 0.6-second spacing, four retries aur in-memory cache settings rakhta hai; HTTP429 par Retry-After ya bounded exponential backoff use hota hai. Yeh source implementation defaults hain, vendor contract ya all-provider global enforcement ka claim nahin. Multi-process shared quota enforcement in process-local structures se establish nahin hota. [[openbb_platform/providers/sec/openbb_sec/utils/ratelimit.py:9]] [[openbb_platform/providers/sec/openbb_sec/utils/ratelimit.py:29]] [[openbb_platform/providers/fred/openbb_fred/utils/rate_limiter.py:38]] [[openbb_platform/providers/fred/openbb_fred/utils/rate_limiter.py:145]]
