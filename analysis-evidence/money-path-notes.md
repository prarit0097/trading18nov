## trader-budget: kitne shares aur kyun

`size.py` standard-library, no-network calculator hai. Default plan mode `size_trade()` long buy hi accept karta hai; missing symbol, nonpositive entry/stop/target, blocked symbol, nonpositive budget, invalid cash-buffer percentage aur supplied date ka aaj ki New York date se mismatch error hai. Missing plan date apne aap reject nahi hoti (`trader-budget/size.py:305`). Market reference = plan entry aur fresh higher quote mein bada number; limit reference = requested limit, chahe plan entry se neeche ho. Stop reference ke neeche aur target upar hona chahiye. Prices half-up cents par round hote hain; shares integer-cent division se floor hote hain (`size.py:243`, `size.py:270`, `size.py:341`).

Four candidate quantities: max-loss/risk-per-share; budget×position-percent/reference; max-order/reference; available-cash/reference. Available cash = budget minus budget-based cash buffer, aur existing portfolio ho to **portfolio cash minus wahi buffer** se bhi capped. Minimum candidate final quantity hai; tie mein first limit headline ban jaati hai. Zero/falsy loss, position, order caps code mein candidate add nahi karte. Position calculation yahan existing ticker holdings subtract nahi karti; downstream risk full account ke saath dobara dekhta hai (`size.py:358`). Quantity zero, unrounded reward:risk minimum se kam, ya resulting cost minimum order se kam ho to refusal result milta hai (`size.py:389`).

Concrete TSLA example: entry364.18, stop358.32, target370.04 → per-share risk5.86. $50 risk cap8 shares, $3,750 position cap10, $4,000 order cap10, $4,500 deployable cash12 → final8; proposal cost$2,913.44, stop-based planned loss$46.88. Higher fresh366.48 quote risk8.16 kar deta hai; quantity6 ho sakti hai, lekin reward:risk≈0.44 hone se proposal refuse hota hai. Yeh max-loss-at-stop estimate hai, guaranteed execution loss ceiling nahi.

`bracket_order()` strings mein `qty`, `take_profit_limit_price`, `stop_loss_stop_price` deta hai; `type=market` (ya limit plus `limit_price`), `time_in_force=day`, `order_class=bracket`. Local `why` aur nested `plan` entry/stop/target/risk_per_share/max_loss/setup/entry_time/flat_by carry karte hain (`size.py:418`). `--write [PATH]` successful proposal ko `{created_by,created_at,status:"proposed",paper,note,source,orders:[...]}` envelope mein replace karta hai. Refusal par naya order nahi likhta, **existing orders file delete bhi nahi karta**; purani proposal disk par reh sakti hai (`size.py:752`, `size.py:775`).

CLI: `python trader-budget/size.py --plan FILE --config FILE --budget N --limit [PRICE] --prices FILE --portfolio FILE --now "2026-10-19 10:15" --write [PATH] --json`. Bare `--limit` plan entry use karta hai; no-offset `--now` New York maana jaata hai. Success0/refusal1 (`size.py:847`).

Legacy weights mode `--weights AAPL=40,KO=60` ya `--targets FILE`, optionally `--top`, `--whole-shares`, `--cents`: duplicate ticker error; blocked/nonpositive weights drop; descending top-N; remaining weights100 par renormalise; investable dollars proportionally allocate; over-cap ticker pin karke remainder redistribute; minimum-order se neeche sabse chhota weight remove karke repeat (`size.py:490`, `size.py:605`). Dollar rounding total ko floor karke difference largest uncapped positions mein adjust karta hai. Whole-share mode first floor, phir affordable one-share additions ticker ko deta hai jo apne allocation se sabse peeche hai (`size.py:544`, `size.py:581`). Idle cash explicitly report hoti hai. Output simple market/day buys hain, fractional mode mein `notional`, whole-share mode mein `qty`, **bracket/stop nahi** (`size.py:684`); default risk rules unhe block karengi.
