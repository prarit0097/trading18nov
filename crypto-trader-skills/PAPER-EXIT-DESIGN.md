# Bounded paper-exit monitoring

Continuation of the owner's crypto workflow goal and the explicitly pending automatic exit check. Supports only simulated Binance spot BTCUSDT/ETHUSDT/SOLUSDT positions; public reads, no authenticated/exchange order endpoint. Existing strategy entry rules, stop/target levels, account risk caps and holdout results remain unchanged.

Choose a foreground bounded watcher instead of a daemon/service: no new infrastructure or invisible lifetime, observable completion and repeatable tests. `paper watch --duration-seconds 60 --poll-seconds 15` runs for a bounded observation interval; default duration0 is one pass. Allowed duration0..3600 and polling5..300seconds. Network calls can extend wall time beyond the nominal interval. `--now`, manual `--price`, input files and fetch switches are rejected for live watching.

For each open position, fetch the public Binance best bid/ask and local request/receipt times. No backfilled or fabricated historical touch. Accept only matching symbol, positive ordered prices, allowed source and aware timestamps with request<=receipt<=current time; request age<=15seconds and request not before position opening. Exchange bookTicker lacks its own event timestamp: only local receipt/request freshness is verifiable, with no latency SLA. A missed touch between polls remains unknown.

Trigger a full paper close when observed bid<=recorded stop or bid>=recorded target. Fill at that observed bid with adverse slippage, round down to the recorded price tick, include exit fee and original entry fee in realized PnL. Never fill retrospectively at the stop/target. Apply accounting under the workspace writer lock, re-read the latest position ID, update cash/inventory/daily realized PnL once, commit the authoritative ledger then recoverable portfolio/orders. Concurrent/manual closures must not produce a second sale. Normal manual close and watcher share one settlement function.

New paper entries retain an exit-model snapshot (venue, spot product, quote currency, tick, fee and slip). Existing manual test entries may use their integrity-checked `assets/<symbol>/config.json` entry archive, with matching symbol/quote/fee and opening time; missing/wrong/corrupt archives block that position. Do not infer BTC settings from the last SOL config, mutate the global config to cycle symbols, or reset account cash. Modeled entry-time filters/costs are explicit assumptions; venue filter changes and full-depth/partial fills are not qualified.

Persist per-asset quote envelopes and `watcher.json` with started/finished times, poll count, bounded recent results, errors and closed order IDs. Source errors leave inventory unchanged and do not prevent other supported positions being checked. No crash lock stealing. The command ends when duration expires or no positions remain; there is no always-on process afterward. A stale quote cannot cause an exit. This is protective-exit mechanics, not evidence of higher expected return.

Before changing trading/core source files, preserve the prior research source snapshot and hashes so the completed rejected pilot remains reproducible. Its final data stays inspected and cannot be retuned/requalified under the new code hash. Unit/integration tests cover stop/target/no-hit, gap fill, fees/daily PnL, stale/future/mismatched quotes, legacy setting resolution, symbol independence, restart/idempotence/concurrent close, malformed data, source errors and CLI bounds. Then run the installed paper wrapper on the existing virtual account for60seconds, report actual closures or no-touch honestly, and explicitly state that monitoring ended.
