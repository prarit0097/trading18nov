## Market data and execution

- The Binance USD-M batches use public BTCUSDT and ETHUSDT perpetual archives whose SHA-256 hashes match Binance's published checksums. Reference runs from 23 September through 20 October 2026, and Later runs from 21 October through 3 November 2026, in IST. The liquid-market follow-up keeps the prior effective intervals where those scripts passed compilation on Delta and were blocked by untraded fills. The market-data follow-up uses 15-minute chart candles with complete, UTC-aligned secondary candles where source rules request the same market at another interval. [Binance public data](https://github.com/binance/binance-public-data)
- The same-symbol provider accepts only the chart market and supported intervals. Its expected timing was independently checked against a known bar-close strategy, a previous-candle offset with lookahead enabled, gaps, and the last confirmed lower-timeframe value. Unknown requests fail without borrowing another feed. A realtime-only calculation setting is ignored only for historical bar-close evaluation. Historical recalculation after fills, magnification and source logic requiring realtime state retain their own coverage dependencies. [TradingView data-request semantics](https://www.tradingview.com/pine-script-docs/concepts/other-timeframes-and-data/) · [TradingView strategy execution](https://www.tradingview.com/pine-script-docs/concepts/strategies/)
- The Heikin-Ashi follow-up derives same-symbol reference series with prior-bar state initialized at the start of the public archive. Orders still use the real chart bars for fills. The helper was checked against an independent calculation and a fixture that consumes the derived input while filling at the primary chart price. The data path is available through `--heikin-only`.
- The PineTS runs use a $10,000 or 10,000 USDT drawdown reference, 1,000 quote-currency units as default entry notional, 5.9 basis points per side for fees and 3 basis points per side for modeled execution costs. Source-sized orders and pyramiding can create different exposure. Win rates count positive closed lots, including completed partial lots. No-close results leave win rates blank. Rows using other engines carry their own documented settings.
- The stricter process sandbox admits quoted text without changing Pine strings. It denies access to project files and outbound networking, with Node file permissions restricted to the isolated public-data directory. The evaluator still checks executable tokens, imported libraries, unsupported feeds and future-looking behavior. The verified sandbox probe is included in the market-data manifest.
- The native FMZ JavaScript group uses the official offline broker with Binance spot feed data. The non-FMZ tests use the Freqtrade and Jesse engines or source-backed TradingView rules, with the parameters, markets and fee model listed by engine. The new Funding column shows signed funding cash flows where available. [Native FMZ spot replay](fmz-native-spot-replay.md) · [Non-FMZ methods](nonpine_replay.md)

The workbook reports monetary figures in the named product's quote currency. These are historical simulation results covering the dates and model listed for each row. Product funding, liquidation, order latency and order-book execution are only reflected where the corresponding engine report includes them. No demo-order execution was involved.

## Reproduce the market-data batches

Use the pinned FMZ source and the public Binance files downloaded by the [liquid-market replay](delta-pine-liquid-replay.md). Export the prior `Test coverage` scope as a JSON object keyed by catalogue ID with `name`, `source`, `status`, `reason` and `url` fields. The `prepare` action of `research.fmz_marketdata_replay` takes that scope, the FMZ ZIP and the Binance archive directory. Run the isolated `delta_pinets_worker.mjs` against the generated candles and candidates and put its output in `out.jsonl` before calling `finalize`. The optional `--isolated-literals` pass requires a no-network OS sandbox with a local-only data directory and a passing `isolation-probe.json`, followed by a reproducible fixture check. The manifest records the public archives, exact settings, results and unresolved inputs.
