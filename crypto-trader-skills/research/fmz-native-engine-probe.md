# Offline FMZ JavaScript runner check

The official `backtest_javascript` WASM package at revision `342baf9e74fdf83f3ef0b4c010200b1c3ddb9924` ran a trusted BTCUSDT perpetual fixture in a no-network Windows AppContainer. Node v24.18.1 restricted filesystem access to the scratch directory with the public inputs. The native simulator opened and closed 0.01 BTC. The native balance and an independent calculation from the two completed orders agreed to within 0.0000001 USDT. Fill prices were 86,235.6 and 86,370.4. Gross P&L was 1.348 USDT, fees were 1.0183754 USDT and net P&L was 0.3296246 USDT. This fixture checks engine and accounting behavior. It is outside the strategy catalogue result count. [Pinned FMZ engine](https://github.com/fmzquant/backtest_javascript/tree/342baf9e74fdf83f3ef0b4c010200b1c3ddb9924)

`VCtx` requests startup history before the documented custom-data setter is available. The pinned implementation's two-argument `exchange.SetData` did not override the ticker when called with the single-array form in the published tutorial. The replay injects actual public market responses at the Node history callback instead. The callback accepts only the requested instrument and window. Binance perpetuals also request a separate funding series on the first futures trade. [FMZ custom-data tutorial](https://www.fmz.com/digest-topic/9106) · [FMZ instrument conventions](https://www.fmz.com/syntax-guide/conventions/symbol)

## Reproduce the fixture

Copy `fmz_native_engine_fixture.cjs` into the isolated scratch directory. Download the pinned `backtest_javascript_wasm.js` into that directory and confirm its SHA-256 is `d2cac831db3b2cdce8c9bf1e5aa35bdbdc695d91464ca6dbf7fe0259a0509be8`. Save the two public response bodies as `swap.json` and `funding.json`. Their response metadata includes service timing, so a fresh download can have a different full-body checksum. The recorded files contained 3,025 BTCUSDT five-minute rows and 31 funding observations. [Public perpetual response](https://q.fmz.com/data/history?detail=true&round=true&feeder=local&event=feed&eid=Futures_Binance&depth=5&trades=0&custom=0&period=300000&symbol=BTC_USDT.swap&from=1789201800&to=1790109000) · [Public funding response](https://q.fmz.com/data/history?detail=true&round=true&feeder=local&event=feed&eid=Futures_Binance&depth=5&trades=0&custom=0&period=300000&symbol=BTC_USDT.funding&from=1789201800&to=1790109000)

Using a one-occurrence text replacement, change `},httpGet=function(url){let options` to `},httpGet=function(url){return globalThis.__offlineProbe(url);let options` and save the adapted package as `fmz-wasm-engine.cjs`. The new callback reads the supplied response body and throws on requests outside the fixture. Run `node.exe --preserve-symlinks --preserve-symlinks-main --permission --allow-fs-read=<scratch> --allow-fs-write=<scratch> fmz_native_engine_fixture.cjs --receipt` inside the AppContainer, with the host time zone set to IST. The expected receipt is stored with the research evidence.
