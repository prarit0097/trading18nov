# FMZ Pine compilation and migration trials

The round-two ledger identified 412 unresolved FMZ sources with compiler, syntax, or migration errors. Four round-three passes used the pinned FMZ archive and the previous 15-minute Binance USD-M Reference and Later windows for BTCUSDT and ETHUSDT. The passes measured 160 strategies and generated 960 result rows. Seventeen strategies recorded zero closed lots. The first pass screened all 412, ran 169, and measured 86. The follow-up measured 25 additional strategies after repairing distinct issues identified by the PineTS parser. [First replay](fmz-round3-compile-replay.json) · [Follow-up replay](fmz-round3-compile-retry.json)

The first pass joins wrapped named arguments and separates comma-delimited global assignments. Those forms are valid Pine, but the previous migration's declaration and recursion checks read them incorrectly. The migration also renames an unshadowed legacy binding while preserving qualified members, argument names, string values, and function calls. The follow-up preserves an archived user-defined function's original dispatch and body when its name collides with a v5 built-in. [TradingView statement syntax](https://www.tradingview.com/pine-script-docs/v5/language/script-structure/) · [TradingView v5 migration](https://www.tradingview.com/pine-script-docs/migration-guides/to-pine-version-5/)

For 15 strategies, a literal source input default fell outside its declared numeric bounds. The **FMZ · Archived input default** variant retains the published literal and drops the conflicting bound. The underlying source is invalid for the replay engine with that bound present, and these results measure the stated variant. A project-authored fixture compared the migration with an independently written v5 control. All six rows matched. The hand calculation used a two-unit position at an entry close of 104 and exit close of 106, giving 4 USDT gross, 3.7522 USDT after modeled fees, and 3.6262 USDT after modeled fees and execution costs per market and window. [Fixture receipt](fmz-round3-compile-fixture.json)

Each market replay used PineTS 0.13.1 and the standard calibrated Binance perpetual broker. The runner applies 5.9 basis points per side in fees and 3 basis points per side in its all-cost estimate. It reconciles fills against traded-candle volume, quantities, commission and reported P&L. The manifests retain document and migrated-code hashes. The execution took place in isolated Windows AppContainers after verifying that tests for outbound networking and access to an outside file both failed.

The last two passes combined the migration with previously verified same-market price references. Of 121 strategies with a `security` request, 62 passed source screening and 40 complete replays reconciled. The final retry reused the exact candles and ran 12 failed sources that changed after two further compatibility edits. Nine reconciled. The edits preserve literal integer inputs by rounding bounds inward and ignoring fractional widget increments for the fixed default. They also replace an unshadowed pre-v4 `period` name with its documented `timeframe.period` equivalent. A second independent fixture checked that the previous completed 60-minute close gated the expected 15-minute trade. [Same-market replay](fmz-round3-compile-feeds.json) · [Same-market retry](fmz-round3-compile-feeds-retry.json) · [Feed fixture](fmz-round3-compile-feed-fixture.json) · [TradingView v4 migration](https://www.tradingview.com/pine-script-docs/v5/migration-guides/to-pine-version-4/)

## Reproduce

Run `python -m research.fmz_round3_compile prepare ARCHIVE FIVE_MIN_DATA FIRST_WORK LEDGER --initial` using the pinned FMZ ZIP, checked Binance files and the round-two ledger. Use the generated `worker.mjs` and `research/delta_pine_compatibility_preflight.mjs` inside the verified no-network process sandbox. Save the replay as `out.jsonl` and parser diagnostics as `diagnostics.jsonl`. Run the module's `finalize FIRST_WORK FIRST_REPORT --diagnostics FIRST_WORK/diagnostics.jsonl` action. Prepare the retry with `--previous-work FIRST_WORK` instead of `--initial` and repeat the isolated worker and finalization. The retry carries forward earlier successful IDs and skips unchanged failed candidates.

Run `python -m research.fmz_round3_compile_fixture FIXTURE_WORK` to stage the independent control. Save its worker output as `fixture-out.jsonl` and use `--verify-to FIXTURE_REPORT` to validate the arithmetic and isolation evidence.

Prepare the same-market replay using `python -m research.fmz_round3_compile_feeds prepare ARCHIVE FIVE_MIN_DATA ONE_MIN_DATA FEED_WORK LEDGER FIRST_REPORT RETRY_REPORT --initial`. Run it with the same isolated runner and call the feed module's `finalize` action. For the final retry, include the feed report among the prior reports and pass `--previous-work FEED_WORK` instead of `--initial`. Use `--feeds` when preparing and verifying the feed fixture.
