# FMZ Pine compiler replay

Three offline passes recovered **69 previously pending strategy IDs and 414 result rows** from the round-three ledger at commit `fd4ad038`. Of those strategies, 64 closed at least one lot and five had no closed lots. Each completed strategy contributed one row per BTCUSDT, ETHUSDT and pooled pair in each of the two existing Binance USD-M 15-minute windows. The result manifests retain the source and migrated-code hashes, the exact candles, the PineTS engine and worker hashes, and all newly observed compile or runtime failures. The first pass restored source-audited previous-bar state for older scripts, renamed conflicting function-local bindings and normalized compatible literal input syntax. The retry restored function-local series history and kept both branches of older `iff()` calls eager. It used the documented RSI ratio formula only where both arguments were clearly volume-weighted float series. The retry also moved constant strings and options into v5 input syntax, used existing enum defaults for fixed-default enum widgets, and named positional input types. [Pine v3 migration guide](https://www.tradingview.com/pine-script-docs/v5/migration-guides/to-pine-version-3/) · [Pine v5 migration guide](https://www.tradingview.com/pine-script-docs/migration-guides/to-pine-version-5/)

The final pass applied 17 source-specific edits against pinned archive documents. These include five v1 scripts moved through the v2 compatibility path, explicit input types, comments for standalone section labels, restored return expressions, and whitespace corrections for audited order blocks. For ID 4730, the offline variant omits an unresolved alert-only declaration. The broker order and signal code remains the archived source. Rows identify pre-existing compatibility variants where applicable, including historical bar-close evaluation and adapting a chart declaration around active archived orders. Strategies with ambiguous input defaults, conflicting declarations, external feeds, missing source symbols, and unresolved broker or loop behavior retain their recorded blockers in these compiler reports.

Each pass ran in a Windows AppContainer that denied a network connection and file reads outside the replay directory. Two project-authored fixtures ran through the same calibrated broker and matched independent v5 controls in all six rows each. A two-unit position opened at 104 and closed at 106 on each market and window. That yields 4 USDT gross, 3.7522 USDT after 5.9 basis points per side in modeled fees, and 3.6262 USDT after an additional 3 basis points per side in modeled execution costs. The second fixture also checks an EMA that must warm up while the other branch is selected, an independent local counter and a 50-point legacy RSI when the two positive inputs are equal. ## Reproduce the offline replays

Use `python -m research.fmz_round4_compile prepare ARCHIVE WORK LEDGER --initial` with the pinned FMZ ZIP and the round-three coverage ledger. Supply `--prior-work` for the round-three compiler retry, initial compiler replay, latest local compatibility replay, compiler feeds replay and compiler feeds retry. The first folder supplies the verified candle file, and `--previous-report research/fmz-round3-compile-retry.json` supplies its published hash. The initial and audited candidate manifests, preflight files, candles and workers reproduced byte for byte. The retry reproduced the same parsed JSON and identical candle and worker files. [Round-three inputs and isolation directions](fmz-round3-compile.md)

Run the generated `worker.mjs` and `delta_pine_compatibility_preflight.mjs` in the same no-network process sandbox. Save `out.jsonl`, `diagnostics.jsonl` and the passing `isolation-probe.json` in the stage directory, then run `python -m research.fmz_round4_compile finalize WORK REPORT`. For the retry, omit `--initial`, pass the first round-four work directory first in `--prior-work`, and provide its report as `--previous-report`. For the audit use `--targeted`, carry forward both earlier round-four work directories and reports, and put the retry work directory first. Prepare fixtures with `python -m research.fmz_round4_compile_fixture WORK`, run the isolated fixture worker and verify with `--verify-to REPORT`. Include `--retry` for the second fixture.
