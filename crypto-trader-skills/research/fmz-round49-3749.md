The literal snapshot has a duplicate version directive and identifiers that shadow `security` and `rsi`. The portable reader removes the duplicate directive and renames only shadowing identifiers. The positional market-close arguments match explicit `when=true` for Long and `when=false` for Short on both markets. Setting both to true changes the native control from 23 to 54 closed BTC trades and from 38 to 63 closed ETH trades.

The pinned broker leaves one anonymous Long take-profit active after `strategy.close("Long")` and a flat interval. The synthetic lifecycle fixture reproduces the old take-profit closing a freshly opened Short at that Short's entry open. Direct reversal, reversal with the old limit marketable at the opening price, and `strategy.close_all` fixtures provide controls. The stale fill appears once on BTC and twice on ETH in the historical tape, and the unbound native ETH run also emits 252 invalid-reservation diagnostics. The verified benchmark binds each authored take-profit to the entry ID of its own active position. Market closes and reversals retain the source rules. This repair is scoped to the saved single-position strategy. [TradingView Pine exit persistence](https://www.tradingview.com/pine-script-docs/v5/concepts/strategies/#exits-for-multiple-entries)

The independent minute ledger matches both markets' signals, each whole-lot position and exit, and per-bar gross cash, inventory value and equity. It uses next-minute opening prints for market orders, price-improving opening prints for marketable resting limits, and the first eligible one-minute range for other limits. Long exit limits round up and short exit limits round down to preserve the price protection. Tick steps are 0.10 BTCUSDT and 0.01 ETHUSDT, with 0.001 base-asset units per lot. An observed print and a theoretical range touch provide historical execution inputs. Actual order execution and queue placement were outside the benchmark.

## Reproduction

1. Pin the source to the FMZ catalogue archive commit `7853bb2bf262c4567ac238d3552d97f0e50cb801`. Check the producer's source SHA and engine SHA. Use the Windows offline AppContainer for the native runtime with filesystem and network denial checked in `round3-isolation-python.json`.
2. Place the official monthly minute and quarter-hour archives in the two data directories, with their published `.CHECKSUM` files. Place the BTC November 10 daily one-minute and individual-trade zip archives next to the sandbox directory, named `sandbox`. The JSON records the exact input receipts. Run `python -m research.fmz_round49_3749_stage MINUTE_ARCHIVES FIFTEEN_MINUTE_ARCHIVES APP_CONTAINER_ROOT` and then `python -m research.fmz_round49_3749_tape PARENT_OF_APP_CONTAINER_ROOT` outside the isolated runtime.
3. In the existing AppContainer research harness, run `fmz_round49_3749_fixture.py` and then `fmz_round49_3749_runner.py` from the sandbox where `source-3749.md`, the market feed, `replay_2864.py`, and `probe_1216.py` are staged. Allow up to 420 seconds for the multi-control native replay.
4. Run `python -m research.fmz_round49_3749 APP_CONTAINER_ROOT OUTPUT_JSON` with the independent ledger and proof checks. Compare the output to `fmz-round49-3749.json`.
