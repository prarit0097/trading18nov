# Expanded native FMZ replay

This pass checks 508 pending FMZ archive entries from the `cb4745c` workbook coverage. It parsed 329 single-entry JavaScript candidates and 103 standalone Python scripts. The coverage array lists a disposition for each of the 508 IDs. It records specific missing source parameters, external data and deployment state, native runtime errors, and order execution requirements where the available evidence identifies them. Spot and futures scripts that need their original queue, depth, funding, or multiple inventory legs remain pending.

Seven strategies completed independently on BTCUSDT and ETHUSDT Binance spot in both windows. IDs 42, 1134, 4391 and 5426 closed lots. IDs 1844, 4380 and 4381 opened inventory and had no closes. The two scheduled-investment strategies 4380 and 4381 ran with the official native Python engine. The report contains 42 result rows and the simulator's individual trade orders and balance checks. [Results and coverage](fmz-native-expanded-replay.json)

The original pinned source code supplies the strategy logic. For 48 selected JavaScript sources, the checker queried the public parameter form linked from the pinned document. It validated the form against the visible source prefix and recovered default values on 42 pages. An explicitly archived setting takes precedence over a displayed form default. The result manifest records page and input digests, source links and applied per-strategy values. The screen can identify a name with no declaration but has no way to prove that every branch uses only available runtime data. [FMZ strategy parameters](https://www.fmz.com/user-guide/strategy-parameters) · [FMZ backtest configuration](https://www.fmz.com/user-guide/backtesting-system/backtest-configuration-and-saving)

Reference spans 23 September–20 October 2026 and Later spans 21 October–3 November 2026, inclusive in IST. The 15-minute trials use native five-minute Binance spot candles. The 4-hour trial for ID 42 preserves the archived 15-minute base and source's eight-hour signal cadence. Its display-only plots are disabled and repeated reads of the same eight-hour bar are skipped. Native time advances through those intervals so the simulator can still settle resting orders. The longer FMZ-requested warmup also uses public spot data. The alternate venue, original or selected chart interval and public provider URLs are recorded with every staged case. [FMZ candle period rules](https://www.fmz.com/lang/en/syntax-guide/fun/market/exchange.getrecords)

The native replay uses 10,000 USDT and zero starting inventory per market and retains each source's order sizes. It uses the market's own quantity minimum for the retired `GetMinStock` function where needed. Venue fees are modeled at 5.9 basis points per side and incorporated into cash and lot calculations. The estimate after all costs also subtracts 3 basis points per side for execution costs. Independent accounting matches the broker's ending cash, inventory and holds, and matches closing fills first in, first out. Order placement timestamps provide drawdown sequencing. The worker snapshots account and resting orders in the last minute, before the simulator's end-of-feed exception. Market data is trade-derived OHLCV. The engine derives execution ticks from those candles. [FMZ order history](https://www.fmz.com/syntax-guide/fun/trade/exchange.gethistoryorders)

## Reproduce

Start with the pinned FMZ ZIP, the baseline `remaining-backtest-coverage.json` from `cb4745c`, and the public cache files listed in the result manifest. The parser screening uses `acorn` and `acorn-walk` supplied by the PineTS installation, plus `eslint-scope@8.4.0` installed in scratch without lifecycle scripts. `fmz-native-js-engine-scope.json` records the engine's inspected globals and exchange methods. Run `python -m research.fmz_native_expanded_replay extract <fmz.zip> <scratch>` with the baseline coverage file in place. Use `fmz_native_expanded_screen.cjs` to produce `native-screen.json` from `native-source-candidates.json` and the engine scope. Then run `python -m research.fmz_native_public_params <scratch>` and screen the resulting `native-enriched-candidates.json` into `native-enriched-screen.json`. Run `python -m research.fmz_native_python_screen <fmz.zip> <scratch>` for the Python screen.

`python -m research.fmz_native_expanded_replay stage research/fmz-native-expanded-replay.json <fmz.zip> <scratch>` reconstructs the native job inputs and checks the market archives and JavaScript engine pin. Run the two workers in separate no-network Windows AppContainers with only local public inputs and set the host time zone to IST. For JavaScript, use Node [with the same filesystem permissions and symlink flags as the native fixture](fmz-native-engine-probe.md). The Python worker uses the published `fmz.py` from upstream Git revision `b6cd4d12f15d88c48d3b416510ca9e48d2e46da7` and the official Windows 64-bit backend. Place the loader at `official_fmz_python.py` and the matching backend under `depends/backtest_py_windows_64bit.so`. The Python worker checks its pinned SHA-256. The trusted AppContainer fixture independently reconciled a round-trip ledger with both engines. [Official Python runtime](https://github.com/fmzquant/backtest_python/tree/b6cd4d12f15d88c48d3b416510ca9e48d2e46da7) · [Python fixture receipt](fmz-native-python-fixture.json)

The JavaScript worker accepts catalogue IDs and writes a JSON Lines receipt per selection. The Python worker takes its selected IDs after the script name and writes `native-trials-python.jsonl`. Each batch has a bounded runtime. List the final receipt filenames in `native-evidence-files.json` and run `python -m research.fmz_native_expanded_replay finalize research/fmz-native-expanded-replay.json <scratch>`. Use only the final receipt for a retried scenario.
